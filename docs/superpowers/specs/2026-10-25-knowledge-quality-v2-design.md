# DSE Knowledge Workbench 품질 보완 v2

사용자가 승인한 보완: Write에서 source 역할·Claim 단위/revision/조건을 구조화하고, KG 개체 연결과 Read를 개선하며, 같은 실제 전체 여정으로 1,000개 규모를 검증한다. 기존 구현·평가 commit은 f2e113c, 고정된 100-source baseline과 30개 공개 regression qrels를 보존한다.

## 구현 선택과 범위

Master의 구현 선택: 기존 Python/FastAPI/PostgreSQL/pgvector/FTS, host Codex CLI gpt-6.1-sol/max, DeepInfra google/embeddinggemma-2 768차원을 유지한다. 새 DB·GPU·weight 다운로드·AWS를 추가하지 않는다. 모델/검색/자료 판단은 근거와 검토 provenance를 보존하고 unknown을 강제 성공으로 바꾸지 않는다. Public에는 source metadata·집계·코드만 게시한다.

### Phase Q1 — 현재 100개의 더 선명한 전체 제품

사용자는 UI/CLI에서 role이 표시된 자료를 찾고, 조건·parameter·source proof가 있는 Claim과 source 간 topic graph를 검토하고, 개선된 검색으로 DSE source 질문에 답변을 받고, metric 입력·HAT schema 구조검증·Melete feedback/재검색·gap/다음 제안까지 실제로 수행한다. 기존 100개 원문과 101개 Claim은 삭제/조작하지 않는다. 새로운 annotation과 source-grounded Claim을 추가한다. 새 ontology는 물리 조립/ISA/kernel correctness를 인증하지 않는다.

### Phase Q2 — 실제 1,000개 전체 제품

Q1의 같은 UI·DSE·feedback 여정을 유지하며 기존 자료목록에서 source 1,000개를 실제 수집·역할 분류·index·검증된 Claim/조건으로 처리한다. Source navigation은 locator로, 무관/미지원/불충분은 별도 상태로 보존한다. 실패·quota·공간 guard·재개와 실제 처리량/토큰을 측정한다. 단순 1,000개 metadata나 mock으로 phase를 끝내지 않는다. 145,748건은 실행하지 않는다.

## Write 계약

Source role enum: core_technical, supporting_method, integration_operations, source_navigation, out_of_scope, unclassified. 역할은 curator annotation이지 scientific authority가 아니다. 기존100의 평가 role은 평가 provenance와 함께 반영한다. 신규자료는 title/head/선택 문맥을 공유 Jev advisory로 분류하고 model/방법/근거 hash/unknown을 남긴다. Role 불명은 검토 필요, out_of_scope는 DSE 근거에서 제외하고 locator는 자료 탐색에 사용한다. Source metadata origin과 실제 acquired fulltext revision scope를 혼동하지 않는다.

Claim context v1 wire shape:

```json
{"schema_version":"claim-context/v1","parameters":[{"name":"metric_or_parameter_name","value":6.4,"unit":"%","evidence":{"chunk_id":"...","quote":"exact source passage"}}],"conditions":[{"dimension":"hardware.from","operator":"eq","value":"V100","unit":null,"evidence":{"chunk_id":"...","quote":"exact source passage"}}],"source_scope_note":"source-specific applicability; unknowns explicit"}
```

Value는 finite scalar 또는 scalar list, operator는 eq/in/between/gte/lte. 조건이 없으면 빈 배열, 값이 근거에 없으면 생성하지 않는다. 단위는 원문값과 normalized representation을 함께 보존하고 알 수 없는 단위는 unresolved로 남긴다. Evidence는 같은 material/revision의 제공 chunk 안의 정확하고 모호하지 않은 인용을 요구한다. validator가 source_start/end와 revision SHA를 계산한다. 숫자·단위/문자값의 literal 근거를 확인하되 이것을 숫자와 metric의 의미 연결/과학적 정확성/일반 적용 가능성 인증으로 바꾸지 않는다. 항상 use_policy=source_assertion_only, validation=literal_grounded_unverified_association, independent_validations=0 상한이다.

기존 claims quote/triple/metadata는 덮어쓰지 않는다. 새 claim_annotations에 context와 extractor/model/proof/version을 append하고 최신 projection을 read에 제공한다. 동일 hash 재처리는 idempotent다. HFpl V100→A100/InfPop와 thermal 동일 capacity/bandwidth 조건 누락은 regression fixture로 둔다. 3/2/1은 최대이며 근거 없는 Claim 수를 강제로 채우지 않는다.

## KG 개체·관계

자유 subject/object phrase를 서로 다른 asset instance로 강제 병합하지 않는다. 기존 assertion edge는 보존한다. 작은 versioned curated alias registry를 이용해 인용에 실제 나타난 KV cache/vLLM/CUDA/HBM/GPU family 등 공통 topic node와 evidence-topic link를 추가한다. H100과 Hopper, A100과 특정 메모리/board revision은 같은 asset으로 합치지 않는다. Topic은 family/concept/interface/metric/software 등 kind를 갖고, quote span·claim/revision을 참조하며 assertion과 별도 relation_kind=topic로 구분한다. `mentions`는 compatibility/causality/inheritance가 아니다. 최대 component 크기를 늘리려고 관계를 만들어내지 않는다.

## Read 계약 (worker B)

Retriever.search(query,category='',limit=12,purpose='auto') 기존3 positional 인수호환. purpose는 auto/design/operations/discovery. Role별 근거 사용을 보존하고 out_of_scope는 일반 DSE 답변에서 제외한다. Auto는 versioned deterministic policy이고 classification uncertainty를 기록한다. Lexical은 full-question AND 대신 quoted phrase/identifier/비stopword 핵심어를 parameterized query로 사용한다. English/Korean 자연어·code token을 지원하되 학습모델 다운로드는 없다.

Dense를 기반으로 lexical/명확한 entity/topic match를 bounded boost하고 흔한 단어 graph OR로 관련없는 source를 올리지 않는다. Graph 후보도 semantic/query relevance로 정렬한다. 후처리 diverse cap은 충분한 candidate pool에 적용하고 빈자리를 채워 evidence가4개로 줄어드는 문제를 피한다. Source 역할·지정 source명·scope·query term과 의미 score를 명시적 deterministic rerank에 사용할 수 있다. 신규 외부 reranker 모델 호출을 필수화하지 않는다. Neighbor 문맥은 원래 chunk ID/text/offset을 유지한 별도 evidence로 추가하며 다른 text를 한 chunk ID에 합치지 않는다.

각 결과는 role/role_metadata와 해당chunk의 최대2 compact claim context ref를 포함한다. Root Store/migration이 이를 제공한다. Snapshot에 retrieval policy/version·context ID·role assessment ref를 보존한다. 필수규칙은 기존처럼 retrieval top-k와 별도다. Embedding-only bounded TTL cache(기본300s/128query)는 exact normalized query+provider/model/dim/task에 묶고 PG 결과는 캐시하지 않는다. Cache hit는 새 provider token으로 과금 기록하지 않는다. Worker는 root DB integration을 기다리지 않고 오프라인 fake Store/Embedding으로 검증한다; 실제모델/DB는 root만 호출한다.

## Builder 검토 후 확정한 ruling — 구현 시 이 절이 우선

1. Q1은 기존101 Claim의 원문·triple을 보존하고 eligible94자료의96 Claim에 context annotation을 backfill한다. Navigation/out-of-scope는 원래 Claim이 있어도 재생성하지 않는다. 새 자료(Q2)는 core3/method2/ops1 Claim 상한의 structured extraction을 사용한다. Worker A는 extract_claim_contexts(document, existing_claims, chat)->list[{claim_id,context}]도 추가한다. API 호출 전에 root가 response cache로 재사용하며 annotation/processing version으로 재개한다.
2. Topic edge는 **기존 Claim과 그 quote/검증된 annotation evidence에만** 붙인다. Claim 없는 chunk의 mention은 이번 phase에 graph assertion으로 만들지 않는다. edges.claim_id FK/NOT NULL을 유지하고 evidence_chunk_id FK와 metadata의 proof quote/source_start/end/revision을 추가한다. relation_kind=topic이면 evidence_chunk_id 필수. Graph read는 topic evidence_chunk_id 또는 기존 assertion의 claim.chunk_id를 사용한다. Claim 없는 locator의 검색은 material/chunk 경로가 담당한다.
3. Context 입력의 value/unit은 source literal raw representation이다. Validator 출력은 이를 value_raw/unit_raw로 보존하고 normalized={value,unit,status}를 별도로 계산한다. 알려진 multiplicative unit(time s/ms/us, W/kW, energy J/mJ, B/KB/KiB/MB/MiB/GB/GiB, token/s·tokens/s·req/s)은 scale을 명시한다. %는 identity로 보존한다. 알 수 없는 단위/offset temperature 변환은 unresolved, 단위 미지정 numeric은 unit_unspecified, 문자/boolean은 not_numeric. unit/value가 source literal에서 확인되지 않으면 자동 추정하지 않는다. parameter는 scalar 또는 동일 scalar type의1..32개 list. condition eq는scalar, in은동일type의1..32 list, between은finite numeric2개/오름차순, gte/lte는finite numeric scalar다. 이 normalization은 semantic association/적용가능성 검증이 아니다.
4. 역할별 policy: design은core(1.0)/method(.9)/ops(.65)를 허용하고 ops의사용상한은workflow/interface reference다. operations는ops(1.0)/core(.8)/method(.7). design/operations의navigation은locators로분리한다. discovery는navigation/core/ops/method를locator 또는source-assertion 범위에서 items로반환하며unclassified는needs_review 표시다. out_of_scope는일반검색에서제외하고 material ledger browse에서는보존한다. auto는문서·목록·어디서찾기/feature-map이면discovery, 설치·설정·API·CI·재현/운영이면operations, 그밖은design. 불명확하면design+role상한을보존하고판정규칙을trace에남긴다. DecisionEngine은기존kind에관계없이기본auto를전달하며 retrieval role policy를LLM에제시한다. required_rules 경로는그대로독립이다.

Stage role assessment에Jev를사용하되정본의과학authority로승격하지않는다.
7. 공개30 회귀에서 드러난 source 선택과 passage 재정렬 충돌은 `retrieval-policy/v2.1`의 일반적인 source-then-passage 정책으로 보완한다. 각 stream의 첫 dense material을 semantic anchor로 택하되, 그 material 안에서는 기존 hybrid 점수가 가장 높은 passage를 쓴다. 나머지 채널 가중치·역할별 사용상한·material당3개 다양성 정책은 유지한다. 역할 가중치는 soft relevance prior이며 authority 등급이나 금지 규칙이 아니다. Operations source가 anchor여도 design의 workflow/interface 사용상한을 그대로 보존하고, source 순위로 검증된 물리 규칙으로 승격하지 않는다. 미분류 source는 anchor에서 제외한다. 질문별 예외·qrel lookup은 금지하고 원래 dense/hybrid 순위와 anchor 선택을 API와 평가 artifact 모두에 남긴다. 기술근거 `items`는 locator를 제외하며 DecisionEngine은 계속 이것만 사용한다. 실제 자료찾기/UI의 `source_results`는 evidence와 locator를 typed 결과로 함께 순위화하되 모든 typed locator의 evidence_authority=0과 사용금지를 보존한다. `locators`도 별도 제공한다. 과거 v1 검색에 navigation 자료가 포함됐으므로 기존 source-search 회귀의 production hybrid는 실제 `source_results`를 같은 k개의 chunk slot으로 평가하고, 기술근거 전용 `hybrid_evidence` 점수는 별도로 모두 보고한다. source의 발견을 기술주장의 검증으로 세지 않는다. 최초 v2의 source@5=22/24, chunk@5=16/24 실패 보고서는 보존한다. 이 정책은 새28 holdout retrieval을 처음 실행하기 전에 고정하고 새 결과로 튜닝하지 않는다.
8. Q2의 실제 `claim_context_value_not_literal` 실패를 같은 입력으로 재현했다. 값이 identifier 내부 부분 문자열이거나 숫자가 없는 인용의 정수 값이므로 validator를 완화하지 않는다. 기존 최대 1회 repair에 실패한 document/claim/parameter/condition의 정확한 경로와 reason code를 bounded feedback으로 전달한다. 최대 8개 경로, 기존 전체 prompt 크기와 2회 provider 호출 상한을 유지한다. 재실패는 `needs_review`다. 실패 structured response는 private `quality-cache/failures`에 revision/operation/request hash와 함께 1 MiB 이하만 보존하고, 초과하면 hash·크기·생략 이유를 남긴다. 이 경로는 validated cache loader가 읽지 않는다. 진단은 원문 인용 검증의 입력이지 과학적 승인 근거가 아니다.
9. Q2에서 embedding transport 실패의 연속 3회 정지와 동일 batch cooldown 재개를 실제 확인했다. 작은 동일 입력의 단독·병렬 시험은 모두 성공해 원인은 아직 확정하지 않았다. `DSE_EMBEDDING_DOCUMENT_TIMEOUT_SECONDS`·`DSE_EMBEDDING_QUERY_TIMEOUT_SECONDS`를 각각 정수 1..120초, 기본 25초로 설정 가능하게 하되 기본값·batch 크기 8·index 상한 2·재시도/circuit 정책·TLS 검증은 그대로 둔다. 실패 시 timeout 값·원래 예외 class·안전한 error kind·시간·HTTP status를 기록하고 bulk failed invocation도 ledger에 남긴다. exception 본문·header·credential은 기록하지 않는다. ledger 실패가 원래 provider error를 바꾸지 않게 한다. 실제 실패의 원인에 맞춘 운영 설정은 별도 근거와 변경 기록으로 결정한다.
10. Q2의 실제 실패 응답 3건을 원문과 대조한 진단에서 identifier 내부 문자열 11개와 revision 전체에서 중복되는 quote 2개가 확인됐다. 원문은 제공됐지만 stateless repair에 이전 typed response를 항상 생략해 field path가 어떤 후보를 가리키는지 충분히 드러나지 않았다. 초기 structured/context prompt에 정확한 complete-token 값·숫자 추론 금지·원문 인용 규칙을 명시한다. Repair는 기존 prompt 한도 안에 맞으면 이전 typed response 전체를 untrusted private candidate로 제공하고, 넘으면 최대 8개 실패 entry의 원형을 bounded context로 제공한다. 그래도 맞지 않으면 omission을 명시하고 기존 안전한 경로 피드백으로 제한하거나 호출을 생략한다. 값을 잘라 실제 값처럼 제시하거나 변환하지 않는다. 이미 유효한 필드를 보존하고 잘못된 optional entry는 수정·제외하도록 하되 조건을 제거해 주장의 적용 범위를 넓히지 않는다. 원문·값·quote는 private model prompt/진단 경로에만 있고 invocation metadata에는 경로·reason·context mode만 남긴다. `REPAIR_POLICY_VERSION`을 별도로 올리며 원문 validator·기존 Claim·검증된 cache·최대 2회 호출·전체 prompt budget은 유지한다. 실제 stage는 중단하지 않고 완료 후 같은 batch를 drain/reload/resume하며 정본과 과금 요청의 exactly-once는 새로 주장하지 않는다.
11. Q2 최종 1,000개 corpus 고정 후 기존 100개·공개 qrel·진단 및 초기 QA에서 본 source를 제외한 NEW900에서 새 holdout을 만든다. 결과를 보지 않는 독립 source-only 작성자가 9개 category와 workload/serving/kernel 추가 quota로 정상 12개 의미 질문의 한·영 번역쌍, 미지원 2쌍을 고정한다(총 28회 질의, 14개 distinct anchor). 고정 seed의 source 순서와 사유 있는 reject 기록을 사용한다. 정상 source Hit@5는 production `source_results`와 기술근거 `items` 각각 raw 5개 chunk slot에서 21/24 이상, 요청 오류 0을 요구하고 지정 chunk 지표는 별도 보고한다. Locator는 기술근거로 인정하지 않는다. 기존 공개 회귀와 필요한 일반 수정은 먼저 끝내고 최종 policy hash를 고정한 뒤 fresh 결과를 처음 실행한다. 실제 model probe 3개(정상 2개·unknown 1개)는 retrieval 결과를 보기 전에 고정하고 모두 knowledge/input={}로 질문만 전달한다. 미지원은 한 문서의 부재를 전체 corpus 부재로 확대하지 않고 제공되지 않은 실행 입력·측정 또는 검증 범위의 한계를 사용한다. 24개 정상 질의는 12개 의미 intent의 상관된 번역쌍이며 precision/전체 recall이나 생산 SLA가 아니다. 빈 평가 표본은 not_evaluated다. Fresh 결과로 조정하면 같은 세트를 다시 blind 성공으로 세지 않는다.
12. Q2 438개 지점에서 Codex 360초 timeout으로 정지한 뒤 동일 실패 자료의 600초 진단에서 두 응답은 384.764초·244.123초에 완료됐지만 전체 context 검증은 실패했다. 응답 복구와 품질 실패를 분리해 보존하며, 600초 운영 시험은 같은 모델·max effort·validator·stage cap을 유지한다. 기존 `retry_max_attempts=3`이 provider 오류를 제외하던 경로를 수정해 같은 자료·stage의 provider attempt도 상한에 도달하면 `failed`/`provider_retry_exhausted`로 끝내고 원래 안전한 오류 code를 보존한다. 이 세 번째 실패도 같은 transaction에서 provider streak에 반영해 연속 3회 circuit을 우회하지 않는다. 중간의 다른 자료 성공이나 batch resume가 소진된 item을 재활성화하지 않는다. Lease fencing·heartbeat·artifact accounting·promotion·다른 retry 정책은 유지한다. 3회는 stage attempt이며 각 extraction의 최대 2회 model 호출이나 CLI 내부 재시도·청구 횟수와 같지 않다. Provider 오류로 끝난 source는 실행 실패이며 무관한 자료나 검증된 KG로 승격하지 않는다. 코드·실제 PG 검증 후 같은 batch를 재개하며 600초는 collection unit 환경에만 적용하고 전체 1,000개 품질 gate는 그대로 둔다.
13. Ruling12의 attempt 상한은 handler 실행 전에 강제한다. 세 번째 lease가 만료돼 결과를 commit하지 못한 경우에도 네 번째 handler를 시작하거나 attempt 수를 늘리지 않는다. `claim_next`는 실제 frozen 상한을 받아 같은 batch lock 안에서, 상한을 소진한 nonterminal item 중 lease가 없거나 만료된 것만 terminal cleanup한다. 유효한 현재 owner의 lease와 정상 세 번째 실행은 보호한다. 이전 같은 stage의 provider retry가 확인되면 `provider_retry_exhausted`/`provider_attempt_outcome_unknown`, 확인되지 않으면 일반 `retry_exhausted`/`attempt_outcome_unknown`으로 보존한다. Unknown outcome을 실제 provider 실패로 단정하거나 provider streak·usage·receipt를 만들지 않는다. 이 정리는 새 stage attempt가 아니며, stale owner의 늦은 stage completion은 fencing을 통과하지 못한다. Stage 상태 commit 앞의 Claim 쓰기나 외부 요청·청구가 정확히 한 번만 발생했다는 보장은 하지 않는다.
14. Q2 평가 helper는 새 corpus의 실제 실행과 과거 실행 재개를 구분한다. `verify-live.py`는 inventory mismatch/조회 실패 시 search·model·feedback·fixture write 전에 실패로 종료하고, fresh output이 이미 있으면 덮어쓰지 않는다. Resume는 base URL·inventory scope·선택적으로 전달한 `corpus_manifest_sha256`가 일치해야 한다. Blind probe helper도 새 output을 기본으로 하고 기존 output은 명시적 `--resume`일 때만 읽으며 base URL·model-visible payload 집합·corpus manifest hash를 함께 검증한다. Scope가 없는 legacy probe report를 새 실행으로 채택하지 않는다. 두 helper는 decision POST 전에 private atomic report에 submission intent를 저장한다. Job ID가 저장된 경우 그 ID를 재사용하고, accepted 여부가 불명확한 intent만 남은 경우 자동 POST를 반복하지 않고 reconciliation 필요 상태로 멈춘다. Server API idempotency나 power-loss 이후 정확히 한 번의 호출·청구는 새로 보장하지 않는다. Probe의 terminal `complete`와 성공은 별도이며, 3개 실제 job 성공·저장 record의 knowledge/input={} 확인을 실행 gate로 둔다. 의미적 answerability 평가는 그 뒤 독립 수행하고, 세 probe 전부를 마친 뒤 native helper의 feedback을 허용한다. Case label·expected ID·scope hash는 감사 정보에만 두고 model payload에는 넣지 않는다. Frozen manifest와 PG의 정확한 ID/revision 일치는 별도 root precondition으로 확인하며 count 일치만으로 이를 주장하지 않는다.
15. Q2 934개에서 저장 용량 목록 조회 실패로 수집이 중단됐으며, 이후 목록은 정상이고 disk·artifact 한도는 충분했다. Historical underlying exception은 sanitized code만 있어 확정하지 않는다. 실제 writer와 scanner를 격리된 임시 디렉터리에서 실행해 raw `.artifact-*` 임시 파일의 strict-name 거부와 prepared JSON의 열거 후 atomic rename에 따른 `FileNotFoundError`를 재현한다. 보완은 전체 inventory pass를 최대 3회, 재시도 사이 50ms로 다시 읽는 범위로 한정한다. 재시도 사유는 사라진 경로와 실제 writer 형식의 owner-only regular raw temporary 파일에 한정하며, partial pass 결과나 실패한 파일을 생략한 합계를 채택하지 않는다. Symlink·잘못된 owner/mode·알 수 없는 파일·권한 오류는 기존처럼 실패로 남기고, 반복되는 transient도 마지막에는 기존 `artifact_inventory_unavailable` storage block으로 끝낸다. 최종 성공은 전체 pass가 기존 trust 검사와 용량 합산을 완료한 경우뿐이다. Immutable baseline·disk reserve·artifact budget·row attempt/lease fencing·provider circuit·모델·추출·read policy는 바꾸지 않는다. 이는 동시 파일시스템의 원자적 snapshot이나 exactly-once 비용을 보장하지 않는다. 실제 file race 재현·negative case·회귀·독립 리뷰를 통과하고 기존 coordinator와 lease가 모두 종료된 상태에서 같은 batch를 reason과 함께 재개한다.
16. Corpus inventory 등록과 KG 처리 완료를 구분한다. Provider attempt 상한 도입 뒤 원문·revision·chunk·vector가 이미 저장됐으나 추출은 `failed/provider_retry_exhausted`로 종료된 자료가 생겼다. 이 native terminal 상태를 `needs_review`나 성공으로 바꾸거나 재시도 상한을 초기화하지 않는다. Metadata-only freeze helper v2는 기존 v1을 보존하고, 같은 canonical/index/artifact/seed100/new900/정확한 집합 검사를 통과한 indexed 자료 중 `failed`·next_stage 없음·active lease 없음도 corpus member로 기록할 수 있다. Terminal state와 안전한 오류 code/kind/stage/cause_code, `indexed_failed_count`, acceptance scope(`indexed_source_inventory_only`)를 보존하며 KG 완료·검증 성공을 뜻하지 않는다고 명시한다. Unindexed 실패는 1,000건에 포함하지 않고, active/미종료 stage·누락된 canonical/index는 계속 freeze를 막는다. 모든 eligible 자료를 분모로 하는 KG 완료율 90% gate와 실제 평가 gate는 별도로 유지하며 eligible failed 자료도 분모에 남긴다. 이는 새 성능 주장이나 실패의 성공 승격이 아니라, native 처리 상태와 자료 inventory의 의미를 맞추는 계약이다.
17. 1,000 corpus의 기존 Q1 paired28 회귀에서 한국어 4개가 기대 source를 top5에서 찾지 못한 결과(20/24)는 보존한다. 두 한국어 질의를 같은 query vector로 실제 PG 비교한 결과, role-visible 18,512개 중 정확 거리 1위인 기대 chunk가 HNSW `LIMIT40`에서 누락됐다. 이는 이 관측의 ANN candidate recall 실패이며 embedding 의미 품질·graph 오류·HNSW 전체의 결함을 뜻하지 않는다. 현재 pilot dense 경로는 같은 role/category/current-revision 범위를 한 read-only repeatable-read transaction에서 세고, 50,000개 이하에서 정확 거리 top40을 계산한다. 50,000은 처리 시간·정확도 SLA가 아니라 명시적인 scan 상한이며 이를 넘으면 제한 오류로 종료한다. ID·거리만 materialize한 뒤 선택된40개의 payload를 가져와 전체 본문을 중간 테이블에 복사하지 않는다. 실제 EXPLAIN에서 HNSW를 사용하지 않음을 확인하고 index DDL·전역 GUC는 바꾸지 않는다. Trace에 exact method·scope 수·상한·limit·policy version을 기록하며 source 사실·KG·HW 검증 성공으로 해석하지 않는다. 별도로 Latin/code와 Hangul 경계 feature를 분리해 `이름+조사`에서도 base 식별자를 보존하고 기존 quoted phrase·escape·feature 상한은 유지한다. Embedding 원문·cache identity·RRF/role/graph weight·semantic anchor·diversity/neighbor/bundle cap·모델·고정 qrels/gate는 유지한다. 기존30과Q1 paired28을 실제 재검증한 후 read policy를 고정하고 그 뒤에만 새28질문과blind3를 만든다. 더 큰 corpus의 ANN은 exact 대비 recall·비용·latency를 검증한 후 별도로 설계한다. 방법의 근거: [pgvector v0.8.2](https://github.com/pgvector/pgvector/blob/v0.8.2/README.md#indexing).
