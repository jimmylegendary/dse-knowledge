# P1 첫 episode: 입력 고정과 실행 차단 상태

상태: **B300 대상 episode blocked, runtime 미실행**. P1의 목표는 요청된 전체 흐름을 작은 재현 가능한 workload로 잇는 것이다. 지금 확인된 HATTorch fixture는 그 흐름의 일부인 SmolLM2 meta forward/census 진단 입력이다. 이를 full episode나 B300 결과로 승격하지 않는다. Pinned source audit는 수행했지만 native DSE run review/committee invocation은 없으므로 run-level `review_completeness=not_run`이다. source pin, 진단 입력, blocker는 [episode-manifest.json](https://github.com/jimmylegendary/dse-knowledge/blob/docs/p0-episode-contracts/fixtures/p0/episode-manifest.json)에 기계 판독 형태로 고정했다.

## 대상 workload와 판정

수용 목표는 NVIDIA B300 HAT plane에서 agent session 1,000개, session당 10–100 turn, turn당 입력 10–512 및 출력 100–1,000 범위를 다루는 것이다. 길이 단위가 token인지, 입력이 매 turn 전체 대화인지 incremental delta인지, arrival 시각/think time과 동시성, prefix 공유·KV 보존·tool wait 기준은 아직 미확정이다. 따라서 숫자만으로 trace를 합성하거나 TTFT/TPOT/session metric을 만들지 않는다. 더 작은 P1 trace는 이 의미를 먼저 고정한 실제 workload의 축소 sample이어야 한다.

Pinned HAT-System source에는 B300 twin/result와 integrated DSE phase run/verdict가 없다고 기록돼 있다. P8은 exploratory/component 상태이며 B300 지원 또는 P1 연결의 증거가 아니다. HAT-System의 L2 serving은 planned/blocked로, L3는 non-runnable로 표시돼 있다. 이 source는 현재 실행 상태 검증이 아니라 지정 commit의 경계 확인에만 쓴다. [HAT-System P8](https://github.com/jimmylegendary/hat-system/blob/e3048fac5704118b47fd7e2eb21ed36d477742a0/docs/plans/master-phase-plan.md#L152), [L2/L3 상태](https://github.com/jimmylegendary/hat-system/blob/e3048fac5704118b47fd7e2eb21ed36d477742a0/docs/architecture/fidelity-level-feature-matrix.md#L159)

| 판정 축 | B300 수용 episode | 아래 B200 진단 입력 |
|---|---|---|
| source_status | source_missing: B300 twin/capability/legality 증거 없음 | source_verified: pin된 twin·model lock·test 존재 |
| runtime_status | blocked; 미실행 | not_run |
| validation_verdict | incomplete_unknown | incomplete_unknown |
| review_completeness | not_run | not_run |
| physical_feasibility | not_assessed | not_assessed; fixture 값만 존재 |
| simulation_permission | denied | denied now. 별도로 선언·승인할 미래 진단 profile에서만 `exploratory_only`를 기대할 수 있으며 현재 grant는 없다. |

이 상태에서 B200의 수치에 scale factor를 곱하거나 B300 baseline으로 이름을 바꾸지 않는다. Cloud build와 실행도 B300 asset/capability와 입력 의미가 고정될 때까지 차단한다.

## Full P1 흐름에 필요한 adapter 계약

모든 phase는 모델·workload·HW·kernel 후보·correctness·HAT fidelity·metric·Melete·다음 제안을 유지하고 증거 해상도만 높인다. 이는 U01–U12의 decision envelope를 축소하거나 일부 단계만 end-to-end인 것처럼 표시하지 않는다. [decisions-and-open-inputs.md](https://github.com/jimmylegendary/dse-knowledge/blob/docs/p0-episode-contracts/docs/decisions-and-open-inputs.md#L9)와 기준 record인 [data-contracts.md](https://github.com/jimmylegendary/dse-knowledge/blob/docs/p0-episode-contracts/docs/data-contracts.md#L75)를 함께 따른다.

## 다음 진행 gate

1. 사용자가 제공할 workload의 length unit, arrival/turn order, full/delta context, prefix/KV, tool wait와 품질 기준을 고정하고 재생 가능한 source trace 및 작은 축소 sample을 고른다.
2. 선택 ModelVersion의 model/tokenizer/config/chat-template·weights identity를 등록하고, 실제 weights quality lane과 meta/dummy 구조 진단 lane을 분리한다.
3. B300 full-hierarchy twin, ISA/ProgrammingModel, per-tier capability·capacity·legality source를 pin한다. B200 twin은 reference probe에만 남긴다.
4. vLLM→HATTorch capture, HATIR candidate generator/lowering, correctness checker, RP snapshot/replay, metric aggregator, Melete outbox/query binding의 각 adapter input/output artifact와 deterministic negative cases를 고정한다.
5. target twin·kernel·recipe·workload 변경 때마다 new run ID로 HATIR cost/coverage와 RP timeline을 recompute한다. 재사용은 동일 immutable key의 verified artifact cache에만 허용한다.
6. 위 계약의 실제 component adapter와 통합 case가 준비되면 deterministic smoke와 External Golden Control을 별도 실행한다. 이번 문서 작성에서는 runtime, test, simulation을 실행하지 않았다.

`source_verified`는 위 파일과 fixture의 존재·내용만 뜻한다. 전체 P1 episode에는 `runtime_status=blocked`, `validation_verdict=incomplete_unknown`, `review_completeness=not_run`, `physical_feasibility=not_assessed`, `simulation_permission=denied`를 유지한다.
